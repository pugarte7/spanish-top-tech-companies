# spanish-top-tech-companies

Companies paying senior software engineers 60k+ **in Spain**. Read
[docs/CONTEXT.md](docs/CONTEXT.md) before changing anything in the data
pipeline — it records why several obvious-looking approaches are wrong.

**The README is the product.** Every company, every salary figure and every
link belongs in `README.md`, generated by `scripts/build.py`. `companies.csv` is
the only data file: one row per salary figure, company columns repeated. Never
slim the README by moving data into side files, and never go back to one file
per company. Both were tried and the maintainer rejected them.

The four things that will bite you:

1. **Levels.fyi serves another country's salaries when it has no Spanish data**,
   and the page currency stays EUR for Germany, the Netherlands, France and
   Ireland. Guard on `percentiles.locationName`, never on currency and never on
   `locationMeta`. `scripts/fetch_spain.py` is the script that writes
   per-company pay; `scripts/fetch_company.py` is details-only for exactly this
   reason. `validate.py` rejects any levels.fyi source URL without `/locations/`
   in it, which is the backstop that catches whatever a fetcher gets wrong —
   leave it in place. This trap has been paid for twice: 682 foreign bands, then
   205 more carried in by a branch cut before the first fix.
2. **The per-location page has three independent sources.** `averages` is the
   company's ladder scoped to Spain — a mean and a submission count per rung,
   and the only source that names a rung, so the only one that yields a senior
   figure; `percentiles` is an aggregate that falls back to another country;
   `median` is one real Spanish submission that survives when the aggregate
   does not. Read all three or you lose most of the data. Map a rung onto our
   ladder only when one of its names says what it is — never by position.
3. **`sampleSize > 0` does not mean a figure is published.** Many companies
   report a count with every percentile null, and
   `generatedOccupationSchema.sampleSize` is the company's *global* count
   whenever `averages` is empty. Only the `averages` counts are Spanish.
4. **Every figure in the payload is USD.** Multiply by `locationExchangeRate`;
   a single submission carries a more precise `exchangeRate` of its own. This
   was missed once and put all 141 bands on the front page 16% high.

All Levels.fyi fetching must run from Spain; the pages are IP-scoped. Keep
`--delay` at 2.5s or more, and treat 403/405/429/503 as throttling rather than
as "not found".

A row should ideally mean the maintainer knows someone in Spain doing that job,
or was offered the position. Crowdsourced figures are placeholders; first-hand
entries (`community`, `offer-letter`) sort above them.

A company with no Spanish pay still gets a row. The `spain_check_*` columns
record which job families were asked and what came back, and the README renders
that as `no Spain data` rather than a dash, so "asked, nothing published" never
reads as "nobody has looked". Never infer that state from the wording of a note.

After any data change: `python3 scripts/validate.py && python3 scripts/build.py`,
and commit the regenerated `README.md` and `companies.csv` — CI fails otherwise.
